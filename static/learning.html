学习过程

每一步都可以被检查和复现。当前方法借鉴正常样本异常检测的“记忆库”逻辑，但使用可解释的颜色区域，而不是不可见的深度特征。

01

正面案例

输入经用户选择的古镇色彩参考图。

02

区域分割

SLIC 将每张图片划分为保持空间连续性的颜色区域。

03

感知色彩

每个区域转换到 CIELAB，并计算中位颜色和面积。

04

平衡记忆

每张图贡献相同权重，减少天空或大墙面的支配。

05

留一校准

每张参考图都与其余参考图比较，建立新颖度基线。

06

证据融合

参考新颖度与当前画面的局部色差共同决定候选排名。

从一张照片到候选排名：算法到底怎么工作？

把流程分成两部分：先从参考照片建立“颜色记忆”，再分析你刚拍的画面。以下步骤对应仓库中的 Python 实现，而非我们自己发明的新算法。

A

离线：建立参考色彩模型

1

收集有限的参考照片

将项目选定的锦溪色彩照片作为比较样本；不是全镇所有颜色的完整数据库。

2

SLIC + CIELAB：切成小色块并记录颜色

SLIC 把照片划分为局部区域；CIELAB 用适合比较颜色的数值描述每块区域。

3

MiniBatchKMeans：提炼颜色原型

对参考颜色进行聚类，保存一组具有代表性的颜色原型，而不是逐张肉眼比较所有像素。

4

Leave-one-reference-out：建立参照基线

轮流留出一张参考图，用剩余图建立比较，再测被留出图片有多不同，以便解释新颖度百分位。

B

在线：分析用户当前画面

1

浏览器取景 → Python 服务

JavaScript/WebGL 负责环视和截图；浏览器将截图发送给 FastAPI 后端，不是在浏览器中训练模型。

2

重新分割当前照片

Python 使用 SLIC 和 CIELAB 提取当前画面的局部颜色区域及其周围颜色。

3

计算两类不一样

局部证据：区域与附近颜色的差异；参考证据：与最接近的参考色原型的差异。CIEDE2000 (ΔE00) 用来衡量感知色差。

4

融合证据 → 候选排名 → 返回可视化

后端融合局部与参考证据，生成候选排名和颜色关系；前端把这些结果画成 Overlay、Network 和图表。

Local Contrast · 和旁边比

想象墙上有一块亮红色装饰，周围都是灰白色：它很显眼，局部对比可能高；但不一定在锦溪参考照片中罕见。

Reference Novelty · 和参考照片比

如果这种颜色在有限的参考照片中不常出现，新颖度可能高；这不等于它在整个锦溪或其他季节都少见。

◎
解释边界： 分数用于确定“先检查哪里”，不能自动决定什么颜色更美、是否符合地方文化、或是否应该移除。当前未使用 PatchCore、Anomalib 或 DINOv2 的深度模型。

实现来源与责任

本项目以 AI 辅助编程（vibe coding）构建原型，采用已有 Python 开源库实现经典方法。SLIC、CIEDE2000 与 MiniBatchKMeans 并非团队原创；PatchCore 仅作为研究灵感。下列源码链接可供逐步审核；算法输出仍需独立测试及社区反馈。

证据边界

下一步需要什么证据？

扩大参考图数量并不自动等于更可靠。数据还需要覆盖不同季节、天气、设备和利益相关者。

    开源研究路线

    我们采用了正常样本异常检测的核心思想，但当前先实现轻量、可解释的颜色记忆。当数据规模扩大后，可以用深度 patch 特征做对照实验。

    PatchCore

    研究先例 · 当前未实现

    PatchCore 使用深度 patch 特征建立记忆库。本原型只借鉴其正常样本异常检测思路，并未运行 PatchCore。

    Official repository ↗

    Anomalib

    研究先例 · 当前未实现

    Anomalib 汇集 PatchCore、PaDiM 等方法，可供未来统一基准测试；当前后端未导入它。

    Official repository ↗

    DINOv2

    研究先例 · 当前未实现

    DINOv2 可在更大数据集上补充物体与材质语义；当前模型不使用它的特征。

    Official repository ↗
